# Topicwake — 제품 요구사항

- 상태: MVP 제품 계약. 구현·검증 여부는 [검증 기준](acceptance.md)과 실제 검사 결과로 판정한다.
- 대상: 같은 내부망의 Zenoh 통신을 조사하는 개발자·운영자.
- 배치: BattleBang과 독립된 `zenoh-admin` 프로젝트. Mac용 Tauri 앱과 기존 로컬 웹 실행을 지원한다.
- 범위: 읽기 전용 관찰, SQLite 로그인, 네트워크 상태, 토픽 검색·정렬·페이로드 확인.
- 배포 자동화: 공개 GitHub 저장소에서 Apple Silicon용 macOS 빌드, 태그 기반 Release와 자동 변경 노트.
  Intel·Universal 빌드는 제외한다. 정확한 발행 조건은 [릴리스 절차](releasing.md)를 따른다.

## 1. 문제와 성공 경험

현재는 Zenoh 데이터 확인마다 임시 Python 구독 스크립트를 만든다. 키 표현식, 발행 주체, 연결 상태를
서로 다른 콘솔에서 추론해야 하므로 “아무 데이터가 없는가, 연결이 안 되었는가”를 구분하기 어렵다.

로그인한 사용자는 한 화면에서 다음 순서로 답을 얻는다.

1. 관찰 서버가 어느 네트워크에 연결되어 있는가?
2. Zenoh 세션이 연결되었는가? 발견되거나 연결된 노드는 무엇인가?
3. 실제 수신한 토픽은 무엇이며 마지막 데이터는 언제 왔는가?
4. 검색한 토픽의 페이로드와 발행 원천에 대한 확인 가능한 정보는 무엇인가?
5. 모르는 정보와 실제 장애는 각각 무엇인가?

## 2. “같은 망이면 전부”의 정확한 제품 의미

같은 SSID·IP 대역은 연결 가능성의 단서이지 전체 Zenoh 가시성의 증명이 아니다. VLAN, AP client isolation,
멀티캐스트 차단, 방화벽, Zenoh mode·scouting·라우팅·ACL 설정에 따라 발견·구독 결과가 달라진다.

MVP는 **관찰 서버의 Zenoh 세션으로 전달되는 샘플의 키를 자동 목록화**한다. 아직 발행되지 않은 키,
연결되지 않은 네트워크, ACL로 차단된 키, 앱 시작 전의 샘플은 보장하지 않는다. UI에는 “전체 네트워크 토픽”이
아니라 “관찰된 토픽”을 표시한다. 목록이 비어도 “토픽 없음”으로 단정하지 않는다.

브라우저·WebView가 LAN Zenoh 패킷을 직접 듣는 구조가 아니다. Rust 수집기를 대상 LAN에서 실행하고
UI는 수집기의 HTTP 스냅샷을 조회한다. Mac 앱은 수집기를 같은 프로세스 안에서 실행한다. 화면의 IP·Wi-Fi는
수집 호스트 기준이며, 앱 포장이 전체 토픽 발견이나 원 발행자 식별을 더 보장하지 않는다.

## 3. 우선순위와 기능 계약

| --- | --- | --- | --- |
| AUTH-01 | P0 | SQLite에 단일 운영 계정과 해시된 비밀번호 저장 | 로그인 후에만 네트워크·토픽 데이터 접근 |

| TOPIC-04 | P0 | 토픽 상세에서 최근 페이로드 확인 | JSON·텍스트·바이너리 구분, 절단 여부 표시 |

| SOURCE-02 | P0 | 연결 상대 주소와 원 발행자 구분 | 라우터 IP를 발행자 IP로 표기하지 않음 |
| UX-01 | P0 | 로딩·빈 상태·장애·세션 만료 처리 | 단순히 숫자 0으로 장애를 숨기지 않음 |
| APP-01 | P0 | Mac 앱에서 수집기와 UI를 함께 실행 | 별도 브라우저·터미널 서버 없이 열림 |
| APP-02 | P0 | 기존 계정의 안전한 첫 이관 | 원본 DB·비밀번호 보존, 기존 앱 DB 덮어쓰기 없음, 앱에서 재로그인 |
| APP-03 | P0 | 단일 인스턴스와 종료 소유 | 중복 실행은 기존 창, 닫기·종료는 수집까지 종료 |
| APP-04 | P0 | 앱 시작 실패·네트워크 권한 안내 | 연결 실패를 로그인 문제나 토픽 없음으로 꾸미지 않음 |

P1은 MVP에서 지원 플랫폼과 구현 상태에 따라 제한될 수 있다. 특히 SSID 조회 실패를 로그인이나 토픽 관찰
실패로 전파하지 않는다. 인터넷 상태는 탐지 대상·시점에 한정된 도달성이고 “인터넷 전체 정상”을 뜻하지 않는다.

### 검색의 범위

UI 검색은 토픽 이름(key expression)만 대상으로 한다. 앞뒤 공백을 제거하고 대소문자를 구분하지 않는
부분문자열로 목록을 좁힌다. 페이로드·출처 IP·ID는 검색하지 않는다. SQLite FTS, 과거 이벤트 검색,
원격 네트워크 스캔은 포함하지 않는다.

### 페이로드 계약

- 수신한 인코딩, 원본 바이트 길이, 수신 시각을 함께 표시한다.
- 유효한 JSON은 들여쓰기하고, 일반 UTF-8은 텍스트로 표시한다.
- 바이너리는 안전한 미리보기로 표시하며 자동 실행·HTML 렌더링하지 않는다.
- 저장 용량을 제한하고 절단 여부를 명시한다. 원본 전체를 보유한다고 주장하지 않는다.
- 수신 시각은 관찰 서버 기준이다. 발행 시각이나 네트워크 지연과 혼동하지 않는다.

## 4. 핵심 흐름

### 첫 실행

계정이 없는 새 설치는 앱 또는 로컬 웹에서 초기 계정을 설정한다. 공개 가입은 제공하지 않는다.
기존 웹 계정을 앱으로 가져온 경우 같은 비밀번호로 다시 로그인한다. 이관·저장 경로는
[아키텍처](architecture.md#mac-앱-저장과-첫-이관)가 소유한다. 성공하면 토픽 탐색기로 이동한다.
기본 계정·하드코딩된 비밀번호는 두지 않는다.
최초 설정 비밀번호는 최소 4 Unicode scalar values, 최대 256 UTF-8 바이트다. 기존 계정의 비밀번호·해시·
세션은 이 최소 길이 완화로 변경하거나 초기화하지 않는다. 앱 이관은 원본을 보존하며 복사본의 세션만 비운다.
짧은 비밀번호 허용은 로컬 전용 도구의 사용자
요구사항이며 외부 공개 보안 적합성을 뜻하지 않는다.

### 관찰과 조사

탐색기에 들어오면 네트워크 상태와 최근 관찰 목록을 본다. 검색을 입력하면 현재 결과를 좁힌다.
정렬을 바꾸고 토픽을 선택하면 상세 패널에서 키·인코딩·크기·원천 근거·최근 페이로드를 확인한다.
실시간 갱신은 선택한 토픽과 사용자가 읽는 내용을 불필요하게 초기화하지 않는다. 화면 일시정지는 표시만
고정하고 서버 수집·HTTP 조회는 계속한다. 재개하면 다음 정상 응답을 표시한다. 5분 경과로 목록에서
숨겨진 선택은 상세에 유지하고 숨김 안내를 표시한다.

### 연결 문제

인터넷이 불가해도 LAN Zenoh는 동작할 수 있다. Zenoh 연결이 실패하면 별도의 오류 안내와 설정 확인
힌트를 보이며, 기존 관찰 자료를 현재 정상 데이터처럼 꾸미지 않는다. 자동 발견이 되지 않는 망에서는
운영자가 서버 측 endpoint/config를 지정한다. UI에서 임의 외부 주소를 입력해 접속하는 기능은 제외한다.
앱의 로컬 네트워크 권한·멀티캐스트·방화벽·발행 상태는 서로 다른 원인이다. 무수신만으로 권한 거절을
단정하지 않으며 권한 변경 후 앱 재실행을 안내한다. 인증 초기 조회에 실패하면 로그인 대신 재시도를 제공한다.

## 7. 출시 판정

[검증 기준](acceptance.md)의 P0 항목을 통과하고, 발견·원천 IP 제한이 UI·문서에 일치해야 한다.

확인만 수행하며 장비 제어 기능을 추가하지 않는다.

## 8. 연속 수신과 UI 갱신 계약

### 현재 구현의 데이터 흐름

Rust 서버는 브라우저 로그인·탭 열기와 독립적으로 Zenoh 세션을 열고 `**` 구독을 연속 소비한다.
샘플마다 키별 최근 payload·누적 건수·누적 바이트·서버 수신 시각을 갱신한다. 브라우저는 이 스냅샷을
주기적으로 조회한다. **샘플 수신 주기와 UI 조회 주기는 다르다.** UI 갱신이 1초라면 그 사이 수백 개 샘플이
와도 최근 하나의 payload와 증가한 누적 건수를 표시할 수 있다. 이것은 전체 메시지 이력 UI가 아니다.

| 값 | 정의 | 오해하면 안 되는 의미 |
| --- | --- | --- |
| 누적 수신 건수 | 이 서버 프로세스가 해당 키에서 처리한 샘플 수 | 네트워크 전체 발행 건수·손실률 아님 |
| 누적 바이트 | 처리한 원본 payload 크기의 합 | NIC 전체 트래픽·대역폭 아님 |
| 최근 수신 시각 | 서버가 최근 샘플을 처리한 시각 | 발행 시각·왕복 지연 아님 |
| UI 갱신 시각 | 브라우저가 스냅샷을 성공 조회한 시각 | 새로운 Zenoh 샘플 도착 시각 아님 |
| 데이터 나이 | 현재 시각 − 서버 최근 수신 시각 | 발행 주체의 장애 확정 아님 |

서버 종료·재시작 시 관찰 메모리와 카운터는 초기화된다. 브라우저 새로고침·로그아웃으로 서버 관찰 카운터를
초기화하지 않는다. 키는 최대 2,000개, 최근 원본 payload 미리보기는 8,192바이트까지 유지한다. 상한에
도달하면 새로운 키를 추가하지 않지만 이미 있는 키는 계속 갱신한다.
Mac 앱은 창 닫기·앱 종료와 함께 수집기도 종료한다. 창 비활성화는 종료나 화면 일시정지로 해석하지 않는다.

### UI 주기와 백그라운드 탭

초기 UI 계약은 약 1초 polling이다. 요청이 끝나기 전에는 중복 갱신을 하지 않는다. 브라우저는 백그라운드
탭의 타이머를 지연시킬 수 있으며 절전·네트워크 상황에 따라 실효 주기는 길어진다. 이때 서버 프로세스가
살아 있고 Zenoh가 전달하는 한 서버 수집은 계속된다. foreground 복귀 후 다음 조회에서 최신 스냅샷과 누적
카운터를 받지만, 그 사이의 개별 payload를 복구하지 않는다.

| New | 첫 관찰·최근 수신을 색상 외 단서와 짧은 표시로 구분 | 전용 신규 배지/애니메이션은 필수 범위 아님 |
| 최근 수신 | 상대 시간과 정확한 시각 제공 | 시간 기반 값은 UI 갱신 간격에 따라 변함 |
| Stale | 마지막 수신 후 <5초 초록·≥5초 빨강, ≥5분 기본 숨김과 보기 토글 | 삭제·장애 확정 아님. 저주기 토픽은 정상이어도 이 기준에 걸릴 수 있음 |
| Hz | 스냅샷 간 `Δcount / 실제 경과 시간` | UI에서 추정. 서버 DTO에는 Hz가 없으며 발행 주파수 보장 아님 |
| Zenoh session open | 수집 세션이 열렸음을 표시 | 특정 발행자와 end-to-end 연결을 증명하지 않음 |
| 무수신 | 세션 열림 + 관찰 샘플 없음/오래됨 | 인터넷 실패·발행자 장애로 단정하지 않음 |
| HTTP 단절 | 이전 스냅샷임을 표시, 갱신 실패 안내 | 기존 데이터가 살아 있는 듯 계속 초록색으로 갱신하지 않음 |
| 탭 백그라운드 | UI 타이머 지연 가능성을 설명 | 수집 중단과 동일시하지 않음 |

Hz를 도입할 경우 새로고침·카운터 reset·시간 역행·첫 관측·긴 백그라운드 구간을 처리해야 한다. 스냅샷 간
평균 수신률은 발행자의 정확한 주파수나 순간 최고 처리량이 아니다. 시계가 다른 브라우저/서버 사이에서
데이터 나이를 계산할 때는 clock skew 가능성을 고려한다.

차이가 해소되면 이 표와 인수 검수 결과를 함께 갱신한다.

### 현재 성능 제한

현재 polling은 모든 키의 최근 preview를 매번 받는다. 최대 2,000개 × 8 KiB이며 binary hex 표현은
약 2배로 커질 수 있어 HTTP 전송·브라우저 메모리·검색 비용이 커질 수 있다. 이는 부하 시험 결과가 아닌
설계 상한 기반 위험이다. 요약 목록/선택 상세 분리는 후속 제안이며 미구현이다. 토픽 이름 검색은 이 분리와 독립적인 UI 계약이다.

### 운영 UI 보완 계약

상세 데이터를 보려고 목록 아래로 강제로 스크롤하게 하지 않는다. 900px 이상에서는 목록 옆 상세,
그 미만에서는 토픽 클릭으로 데이터 화면으로 전환하고 목록 복귀 버튼을 제공한다. 1100px 이상에서는
좁은 네트워크 정보 레일을 함께 표시한다. 가운데 최대90rem 프레임과 패널 간 여백으로 무제한 확장을
제한한다. 데이터는 메타데이터 설명보다 먼저 표시한다. 기본 문구는
운영자가 쓰는 짧은 한국어로 유지하고 기술 설명은 접힌 도움말로 옮긴다. 실제 LAN 데이터와 mock 예시는
구분하며 검증용 mock 결과를 네트워크 자동 발견 성공이라고 보고하지 않는다.
